## 1. プロジェクト概要

### 1.1 目的
**「現在使用している管理アプリの使いづらさを解消し、自分にとって最高の使い勝手を実現する」**

### 1.2 ターゲットユーザー
* **個人ユーザー**（自分自身のトレーニング管理を効率化したい方）

### 1.3 主な機能

**実装済み**
* **筋トレ記録:** 部位・種目・重量・回数・セット数の登録
* **グラフ表示:** 種目を選択し、トレーニング強度の推移をラインチャートで可視化
* **種目管理:** 部位（カテゴリ）とトレーニング種目の追加・削除

**今後実装予定**
* **有酸素運動記録:** 運動種目・時間・距離の管理
* **カレンダー表示:** 過去の実施日を一覧で確認（Google Calendar APIを使用してGoogleカレンダーと連携）

### 1.4 公開URL
* **アプリ本体（フロントエンド）:** https://muscle-training-management.vercel.app
* **API（バックエンド）:** https://muscle-training-management.onrender.com
  * ※ Renderの無料プランで稼働しているため、一定時間アクセスがないとスリープし、初回アクセス時に起動まで数十秒かかることがあります

## 2. システム要件

### 2.1 機能要件

| No | 機能名 | 説明 | 優先度 | 状況 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 筋トレ記録 | 種目、重量、回数、セット数を入力し保存する | 高 | ✅ 実装済み |
| 2 | 種目管理 | 部位・種目のマスタデータを追加・削除する | 高 | ✅ 実装済み |
| 3 | グラフ表示 | 種目ごとの重量の推移をラインチャートで表示する | 低 | ✅ 実装済み |
| 4 | 有酸素運動記録 | 種目（ランニング等）、時間、距離を入力し保存する | 高 | 未実装 |
| 5 | カレンダー表示 | 記録がある日をカレンダー上で可視化し、選択すると詳細を表示する | 中 | 未実装 |
| 6 | マイページ | ユーザーのプロフィール編集や目標設定を行う | 中 | 未実装 |
| 7 | タイムライン | 他ユーザーの筋トレ投稿を表示する | 低(追加予定) | 未実装 |
| 8 | いいね機能 | 刺激を受けた投稿にリアクションする | 低(追加予定) | 未実装 |

### 2.2 非機能要件
* **性能:** ジムの不安定な通信環境でもストレスなく利用できるよう、表示速度の高速化を図る(SPAの使用)
* **セキュリティ:** パスワードはハッシュ化して保存し、万が一の流出時も解読不能な状態にする
* **ユーザビリティ:** スマホを片手にトレーニングすることを想定し、PC画面とモバイル画面のどちらも設計する
* **保守性:** コードの書き方を統一し読みやすく保つ

## 3.　技術スタック

### 3.1 開発環境
* **言語:** C# 13 / TypeScript 5.x
* **フレームワーク:** ASP.NET Core 9.0 / React 19.x
* **ビルドツール:** Vite 7.x
* **IDE:** Visual Studio Code
* **バージョン管理:** Git＋GitHub

### 3.2 使用ライブラリ・パッケージ
| パッケージ名 | 用途 | バージョン |
| :--- | :--- | :--- |
| Entity Framework Core (Npgsql) | C#からSQLを書かずにDB操作を行う（ORM） | 9.x |
| Swashbuckle.AspNetCore | APIの仕様書（Swagger）を自動生成しデバッグを効率化する | 10.x |
| React Router | SPAの画面遷移を管理する | 7.x |
| Chart.js / react-chartjs-2 | 筋トレの成長記録をグラフ化する | 4.x / 5.x |

### 3.3 データベース
* **DBMS:** PostgreSQL(C#と互換性が高く無料で使えるため採用)
* **本番環境:** Supabase（Session Pooler経由で接続）
* **開発環境:** ローカルのPostgreSQL（Docker）

### 3.4 その他のツール
* **コンテナ:** Docker（本番APIはDockerコンテナとしてRenderにデプロイ）
* **テスト:** 未導入（バックエンドにxUnitでの単体テストを導入予定）
* **CI/CD:** 未導入（GitHub Actionsを導入予定）

## 4. デプロイ構成

| 役割 | サービス | 備考 |
| :--- | :--- | :--- |
| フロントエンド | Vercel | Reactアプリを配信 |
| バックエンドAPI | Render（無料プラン） | Dockerコンテナで稼働。無アクセス時はスリープする |
| データベース | Supabase | PostgreSQL。Session Pooler接続を使用 |

※ DB接続文字列はRenderの環境変数 `ConnectionStrings__DefaultConnection` で管理しており、リポジトリには含めていません。
